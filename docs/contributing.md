# Правила разработки

## Общие принципы

- **Логика — в `src/domain/` и `src/data/`, а не в компонентах.** Компоненты отображают данные и передают действия пользователя. Всё, что можно проверить без браузера, выносится в чистую функцию и покрывается unit-тестом.
- **Домен не знает о браузере.** Никаких `window`, `document`, `localStorage` и `fetch` в `src/domain/`: код калькулятора выполняется в Web Worker и в Node.
- **Режим цен передаётся явно.** Функции, которые зависят от цен, получают `priceMode` (и остальную политику цен) аргументом, а не читают глобальное состояние.
- **Жёсткие условия и мягкие предпочтения не смешиваются.** Жёсткие условия (бюджет, `maxWeight`, обязательные модули, глушитель, прицел) делают билд недействительным. Мягкие (пороги характеристик, приоритеты) только ранжируют действительные билды.
- **Новое поведение калькулятора — только с регрессионным тестом.**
- **Внешние данные не заслуживают доверия.** Ответы tarkov.dev, содержимое `localStorage` и импортируемые файлы всегда проверяются и нормализуются перед использованием.

## Стиль кода

- JavaScript (ES-модули) и JSX, без TypeScript. В импортах указывайте расширение файла: `'./priceMapper.js'`.
- ESLint ([`eslint.config.js`](../eslint.config.js)): рекомендуемые правила, правила хуков React и `react-refresh`. Перед коммитом — `npm run lint`.
- Отступ 2 пробела, одинарные кавычки, точки с запятой, висячие запятые в многострочных литералах.
- Константы-перечисления замораживаются (`Object.freeze`) и называются `UPPER_SNAKE_CASE`.
- Комментарии объясняют **почему**, а не что делает код; их немного, и они на английском, как и весь код.
- Хуки и компоненты конфигуратора лежат рядом со страницей: `features/configurator/hooks/` и `features/configurator/components/`.

## Локализация

Интерфейс переведён на английский и русский. Код: [`src/i18n/`](../src/i18n/).

- Сообщения разбиты по файлам (`uiMessages.js`, `configMessages.js`, `pageMessages.js`, `settingsMessages.js`, общие — в `messages.js`). В каждом файле есть объекты `en` и `ru`, которые объединяются в `messages.js`.
- Ключи именуются с точками по области: `config.generate`, `builds.compare`, `ui.diagram.slot`.
- В компоненте:

  ```jsx
  const { t, language } = useI18n();
  t('builds.parts', { count: 3 });
  ```

- Подстановка — `{name}`. Множественное число — синтаксис ICU через `Intl.PluralRules`:

  ```js
  'builds.exportedCount': 'Exported {count} {count, plural, one {build} other {builds}}.'
  // ru: '{count, plural, one {…} few {…} many {…} other {…}}'
  ```

- Если ключа нет в выбранном языке, используется английский текст; если нет и его — показывается сам ключ. **Каждый новый ключ добавляйте в оба языка.**
- Имена предметов и торговцев не переводятся вручную — они приходят из tarkov.dev на выбранном языке.
- Ошибки и предупреждения калькулятора передают `code` и `params` для перевода в UI и английский `fallback`.

## Иконки

Используется самостоятельно размещённое подмножество шрифта **Material Symbols Outlined**: приложение не зависит от CDN и работает офлайн.

1. Добавьте имя иконки в [`src/ui/materialSymbolNames.js`](../src/ui/materialSymbolNames.js).
2. Выполните `npm run icons` — скрипт скачает новый `src/assets/fonts/material-symbols-outlined.woff2`.
3. Используйте компонент: `<MaterialSymbol name="settings" />`.

В dev-режиме иконка, которой нет в подмножестве, вызывает предупреждение в консоли, а тест `tests/ui/materialSymbols.test.js` проверяет, что все используемые имена есть в списке.

## Стили и тема

- Все стили — в [`src/index.css`](../src/index.css), без CSS-модулей и CSS-in-JS.
- Цвета, отступы, шрифты и поверхности задаются токенами (`--bg-base`, `--text-primary`, `--color-gold`, `--spacing-md`, `--surface-panel`…) в блоках `[data-theme="dark"]` и `[data-theme="light"]`. В правилах используйте токены, а не конкретные цвета, — тогда стиль работает в обеих темах.
- Шрифты: IBM Plex Sans (текст), JetBrains Mono (числа и характеристики), Oswald (заголовки).
- Мобильная вёрстка: при ширине меньше 768px навигация переходит в нижнюю панель.
- Учитывайте `prefers-reduced-motion`: анимации загрузки при нём не двигаются (это проверяет e2e-тест).
- Диалоги ([`ModalDialog`](../src/ui/ModalDialog.jsx)) удерживают фокус внутри и возвращают его на кнопку, которая их открыла.

## Аналитика

[`src/features/analytics/`](../src/features/analytics/) подключает Umami Cloud:

- считаются только визиты на `invex0811.github.io`; dev-сервер, preview и e2e ничего не отправляют;
- скрипт загружается при первом событии; если его заблокировали, трекинг отключается до конца сессии;
- просмотры страниц отправляются как обычные пути (`/configure/<id>`), хотя приложение использует `HashRouter`;
- собственное событие сейчас одно — `weapon-open` с `normalizedName` оружия.

Каждое поле `data` в событии Umami считается как ещё одно событие в месячном лимите, поэтому держите данные событий минимальными. Персональные данные не отправляются.

## Типовые задачи

### Новая настройка пользователя

1. Функции `load…Preference` / `save…Preference` в [`buildPreferences.js`](../src/data/settings/buildPreferences.js) с ключом `tarkovGunHelper.<имя>`, обработкой исключений и нормализацией.
2. Если настройка глобальная — провайдер или существующий контекст в `src/features/`. Если относится к билду — состояние конфигуратора и при необходимости `settings` в снимке билда.
3. Если настройка влияет на расчёт — поле в `options` калькулятора и тест в `tests/calculator/`.
4. Если она должна переноситься — ключ в `EXPORTED_SETTING_KEYS` ([`serializer.js`](../src/features/buildTransfer/serializer.js)).
5. Тексты на обоих языках и строка в таблице [Хранение](storage.md#localstorage).

### Новая страница

1. Компонент в `src/pages/` (или в `src/features/<фича>/`, а в `pages/` — реэкспорт, как сделано для конфигуратора).
2. Ленивый маршрут в [`App.jsx`](../src/App.jsx) внутри `<Suspense>`; при необходимости — пункт в `NAV_ITEMS` и иконка.
3. Строка в таблице маршрутов в [Архитектуре](architecture.md#маршруты).

### Новое поле из tarkov.dev

1. Проверьте, что поле есть в JSON API (`json.tarkov.dev/regular/items`).
2. При необходимости нормализуйте его в [`itemMapper.js`](../src/data/tarkovApi/itemMapper.js).
3. Если изменилась форма каталога — увеличьте `PERSISTENT_CACHE_SCHEMA_VERSION` в [`catalogCacheSchema.js`](../src/data/cache/catalogCacheSchema.js).
4. Обновите фикстуры (`tests/fixtures/tarkovJson.js`, при необходимости — моки e2e).

## Коммиты и pull request

- Работа ведётся в отдельной ветке, в `main` — через pull request. CI должен быть зелёным.
- Сообщения коммитов — в стиле Conventional Commits: `feat(configurator): …`, `fix(calculator): …`, `refactor(data): …`, `test: …`, `docs: …`.
- В описании PR укажите, что изменилось для пользователя и как это проверено.
- При изменении поведения обновите документацию в `docs/` и, если меняется функциональность для пользователя, корневой `README.md`.
