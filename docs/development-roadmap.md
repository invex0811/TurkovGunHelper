# Дорожная карта

Что уже есть в приложении и что осталось сделать. Оба списка сверены с кодом (октябрь 2026). Сделанная задача переезжает из второго списка в первый вместе с PR, который её закрывает.

Идеи и баги от пользователей собираются в [GitHub Issues](https://github.com/invex0811/TurkovGunHelper/issues); сюда попадает то, что решено делать.

## Сделано

**Калькулятор**

- Разбит на модули в [`src/domain/calculator/`](../src/domain/calculator/): поиск кандидатов, оценка веток, скоринг, ограничения, статистика, цены, кэш расчёта. Модель расчёта описана в [Калькуляторе билдов](calculator.md).
- Три цели билда: Meta, ограничения характеристик, приоритеты характеристик (по порядку или по весам).
- Жёсткие условия: бюджет, максимальный вес, глушитель (разрешить / запретить / требовать), прицел и кратность, ЛЦУ и фонарь, ёмкость магазина, обязательные модули.
- Расчёт в Web Worker с отменой предыдущего запроса.
- Регрессионные тесты на реальных фикстурах в `tests/calculator/`.

**Цены и данные**

- Статический JSON API tarkov.dev, отдельные каталоги для PvP и PvE и для каждого языка.
- Барахолка, торговцы и бартеры; уровни торговцев, торговец Ref и доступ к Барахолке как настройки.
- Кэш каталога в памяти и в IndexedDB (stale-while-revalidate), работа офлайн на ранее загруженных данных, индикатор свежести и ручное обновление цен.

**Конфигуратор и билды**

- Конфигуратор разбит на компоненты и хуки (`features/configurator/components/`, `hooks/`).
- Ручная замена деталей и цепочек замен, интерактивная схема билда, отметки «уже есть», ссылки на tarkov.dev.
- Сохранение до 100 билдов, сравнение до 4, экспорт и импорт файлов, ссылки на билды.
- Запоминаемые настройки: цель билда, политика цен, тактические устройства, обязательные модули для каждого оружия.

**Интерфейс и сайт**

- Каталог оружия с поиском, фильтрами по типу, калибру и торговцу, сортировкой и избранным; состояния загрузки, пустого списка и ошибки с повтором.
- Сравнение модулей одной категории.
- Интерфейс на английском и русском, тёмная и светлая темы, мобильная вёрстка с нижней панелью навигации.
- PWA: установка, офлайн-оболочка, обновление service worker.
- Обычные адреса, статические страницы для каждого оружия, `sitemap.xml` — см. [Адреса страниц и SEO](seo.md).
- Страница 404 для неизвестных адресов и оружия, кнопка «Feedback» на GitHub Issues.
- Аналитика Umami без персональных данных.

**Разработка**

- Unit-тесты на `node:test`, e2e на Playwright, CI на pull request и автоматический деплой на GitHub Pages — см. [Тестирование и CI](testing.md).
- Документация для разработчиков в `docs/`.

## Не сделано

### Калькулятор

- **Альтернативные билды.** Калькулятор возвращает один лучший билд. Можно показывать два-три близких по оценке варианта с другими ключевыми модулями.
- **Разбивка оценки.** Пользователь не видит, почему выбран именно этот билд: какой вклад дали эргономика, отдача, вес и цена.
- **Закрепить деталь и пересчитать остальное.** Сейчас обязательный модуль задаётся только до генерации; закрепить деталь из готового билда и пересобрать вокруг неё нельзя.
- **Исключить предмет.** Нельзя запретить конкретный модуль, чтобы калькулятор больше его не предлагал.
- **Учёт патронов.** Калибр и патроны в расчёте и в рекомендациях не участвуют.

### Конфигуратор и интерфейс

- **Дальше разбивать `ConfiguratorPage.jsx`.** В файле около 2700 строк: загрузка, восстановление билда, подбор прицелов и замен всё ещё живут в одном компоненте.
- **Inline-стили.** В JSX осталось около 40 `style={{…}}` в 12 файлах; их стоит перенести в классы `index.css`.
- **Недавние оружия** на главной.
- **Пресеты билдов** — готовые наборы настроек (например, «бюджетный», «минимальная отдача»).
- **Профиль игрока.** Уровень персонажа вместо отдельного переключателя доступа к Барахолке.

### Качество и релизы

- **Визуальные регрессионные тесты** (скриншоты Playwright).
- **Changelog и релизы.** Сейчас изменения видны только в истории коммитов и PR.

### Только если понадобится

Эти задачи противоречат решению делать приложение без сервера, поэтому в план не входят:

- backend или прокси для данных tarkov.dev и серверный кэш;
- источники цен, которым нужен API-ключ;
- полный конструктор снаряжения (броня, разгрузка, шлем).
